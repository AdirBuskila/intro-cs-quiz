# חיפוש בינארי

## מה המבחן שואל
כמעט בכל מבחן. לרוב לא חיפוש רגיל אלא וריאציה על מערך עם תכונת סדר: מערך ממוין עם חורים (מצא איבר חסר, או `arr[i] == i`), מערך מסובב (מצא מינימום), מערך שמורכב משני חלקים ממוינים, ספירת מופעים, או האיבר הראשון שמקיים תנאי. נדרש `O(log n)` ואסור לעבור על כל המערך.

## הרעיונות המרכזיים
- התנאי: המערך (או התכונה שמחפשים) מונוטוני. בכל צעד זורקים חצי שהתשובה בוודאות לא נמצאת בו.
- משתמרים `low`, `high` וקריטריון הכרעה על `mid`. לולאה `while (low <= high)`.
- חיפוש "הראשון שמקיים": לא עוצרים ב-`mid` שמצא, אלא שומרים אותו כתשובה וממשיכים שמאלה.
- ספירת מופעים: מוצאים את המופע הראשון ואת האחרון ומחסרים (שני חיפושים, עדיין `O(log n)`).
- מונוטוניות סמויה: במערך שלמים עולה ממש, `arr[i] - i` אינו יורד, ולכן אפשר לחפש בו איפה `arr[i] == i`.

## תבניות C מדויקות
```c
int binSearch(int* arr, int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] == key) return mid;
        if (arr[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

/* אינדקס ראשון שבו arr[i] >= key (מערך עולה) */
int first = n;
int low = 0, high = n - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (arr[mid] >= key) { first = mid; high = mid - 1; }
    else low = mid + 1;
}

/* מינימום במערך ממוין מסובב (ערכים שונים) */
int low = 0, high = n - 1;
while (low < high) {
    int mid = (low + high) / 2;
    if (arr[mid] > arr[high]) low = mid + 1;
    else high = mid;
}
/* arr[low] הוא המינימום */
```

## מלכודות נפוצות
> 🪤 `low = mid` או `high = mid` בלי `+1`/`-1` בלולאה עם `<=` נתקעת לנצח. בגרסת `low < high` ההתקדמות נעשית אחרת, ולכן שומרים על התבנית עד הסוף.

> 🪤 `(low + high) / 2` עלול לגלוש עבור גדלים ענקיים. `low + (high - low) / 2` בטוח. בתרגילי מבחן שניהם מתקבלים.

> 🪤 שימוש בחיפוש בינארי על מערך לא ממוין, או ממוין בסדר יורד כשהקוד מניח עולה.

> 🪤 החזרת `-1` או אינדקס: קראו את הדרישה. אם יש כפילויות, איזה מופע מחזירים?

> 🪤 סיבוכיות: לולאה שחוצה את הטווח בכל איטרציה היא `O(log n)`. אם בתוכה יש עוד לולאה על `n`, כבר לא.

## דוגמה פתורה
מערך עולה ממש של שלמים. "האם קיים `i` כך ש-`arr[i] == i`?"
```c
int fixedPoint(int* arr, int n) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (arr[mid] == mid) return mid;
        if (arr[mid] < mid) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```
הנימוק: הערכים שלמים ועולים ממש, ולכן `arr[i] - i` אינו יורד. אם ב-`mid` מתקיים `arr[mid] < mid`, כל האיברים משמאל עדיין קטנים ממש מהאינדקס שלהם, ולכן ממשיכים ימינה.
